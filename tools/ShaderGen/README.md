# ShaderGen — one WGSL source, three committed shader languages

Brief em3d-28 R-em3d28-1c. The 3D viewer's route A draws with each platform's own GPU API (Metal on
macOS, D3D11 on Windows, Vulkan on Linux), and all three run **one** shader: a WGSL file, cross-compiled
**offline** by [naga](https://crates.io/crates/naga) (MIT OR Apache-2.0) into `.metal`, `.hlsl` and `.spv`.
The generated files are committed; nothing here is built by `dotnet build` or shipped.

It calls naga's **library**, not its CLI, because the CLI has no MSL binding map and emits a placeholder
(`[[user(fake0)]]`) that needed a hand fix-up (spike findings §5.4). Here every binding is stated.

## Build and run

```bash
cd tools/ShaderGen
cargo build --release                                   # naga pinned to =30.0.1 in Cargo.toml

target/release/shadergen <dir>/scene.wgsl <dir>         # writes scene.metal, scene.hlsl, scene.spv
target/release/shadergen --check <dir>/scene.wgsl <dir> # exit 0 = all current, 1 = stale/missing/no hash
```

The spike's shaders: `target/release/shadergen ../Viewer3dSpike/shaders/scene.wgsl ../Viewer3dSpike/shaders`.

## What it guarantees

| Output | Target | Uniform block `@group(0) @binding(0)` | Vertex input |
|---|---|---|---|
| `.metal` | MSL 2.3 (macOS 11+) | `[[buffer(1)]]` in every entry point that uses it | `[[stage_in]]` — attributes 0, 1 from buffer 0 through the pipeline's vertex descriptor |
| `.hlsl` | Shader Model 5.0 (`vs_5_0`/`ps_5_0`, the OS's d3dcompiler_47) | `cbuffer … : register(b0)`, `row_major` matrices | semantics `LOC0`, `LOC1` |
| `.spv` | SPIR-V 1.0 (any Vulkan 1.0 driver) | descriptor set 0, binding 0 | locations 0, 1; clip-space y flipped (`ADJUST_COORDINATE_SPACE`) so one camera matrix serves all three APIs |

- **Deterministic.** Every naga option is set explicitly (its SPIR-V default flips a DEBUG flag with the
  tool's own build profile). The same WGSL gives byte-identical outputs.
- **Valid.** The SPIR-V is re-read by naga's own SPIR-V front end and re-validated before it is written,
  and passes `spirv-val --target-env vulkan1.0` (checked with spirv-tools on Ubuntu 24.04).
- **Each output records the SHA-256 of the WGSL's exact bytes** (lowercase hex), so a test can fail when
  the WGSL is edited without regenerating (brief 28 gate 1b):
  - `.metal` / `.hlsl`: the **first line** is
    `// generated by tools/ShaderGen from scene.wgsl — do not edit; wgsl-sha256: <hex>`
  - `.spv`: an **`OpSourceExtension "wgsl-sha256:<hex>"`** instruction (opcode 4). Not
    `OpModuleProcessed`, the semantically closer one: it needs SPIR-V 1.1, and spirv-val rejects it in a
    1.0 module.

## Checking the hash from C# (the gate)

```csharp
static string Sha256Hex(string path) =>
    Convert.ToHexStringLower(System.Security.Cryptography.SHA256.HashData(File.ReadAllBytes(path)));

// .metal / .hlsl — the first line
static string? TextHash(string path)
{
    string first = File.ReadLines(path).First();
    int at = first.IndexOf("wgsl-sha256: ", StringComparison.Ordinal);
    return at < 0 ? null : first[(at + "wgsl-sha256: ".Length)..].Trim();
}

// .spv — scan the instruction stream for OpSourceExtension (opcode 4) carrying "wgsl-sha256:<hex>"
static string? SpvHash(string path)
{
    var b = File.ReadAllBytes(path);
    var w = System.Runtime.InteropServices.MemoryMarshal.Cast<byte, uint>(b);
    if (w.Length < 5 || w[0] != 0x07230203) return null;
    for (int i = 5; i < w.Length;)
    {
        int count = (int)(w[i] >> 16), op = (int)(w[i] & 0xffff);
        if (count == 0) return null;
        if (op == 4)
        {
            var lit = b.AsSpan(4 * (i + 1), 4 * (count - 1));
            int nul = lit.IndexOf((byte)0);
            string s = System.Text.Encoding.UTF8.GetString(nul < 0 ? lit : lit[..nul]);
            if (s.StartsWith("wgsl-sha256:")) return s["wgsl-sha256:".Length..];
        }
        i += count;
    }
    return null;
}
// assert TextHash(metal) == TextHash(hlsl) == SpvHash(spv) == Sha256Hex(wgsl)
```

A WGSL checked out with CRLF line endings hashes differently from the LF bytes it was generated from;
give the `.wgsl` `-text` (or `eol=lf`) in `.gitattributes` beside it.
