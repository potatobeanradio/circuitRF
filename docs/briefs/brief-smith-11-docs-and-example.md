## 0. What this brief delivers

The parts that make the tool findable: a user chapter with figures, a shipped example `.csmith`, and the
design note's own status line moved from PROPOSED to BUILT.

**It is also the brief that drives the feature as a user**, which is where railRF's own closeout found six
defects that no test had reported. Expect to find some; each one **ships a test that fails at HEAD**.

## 1. `R-smith11-1` — the user chapter

One chapter under `docs/user/src/`, generated by the docs factory like every other. What it has to cover,
in the order someone meets it:

- what the tool is for, and **when to use the Match Designer instead** — the two are answers to different
  questions and a user who reaches for the wrong one wastes an afternoon;
- stating a generator, including importing an `.s1p` and the one-click Conjugate;
- building a cascade, and **what the per-element curve means** — this is the idea the whole tool is built
  on and it is the one sentence that has to land;
- dragging a gripper, and what happens downstream;
- the per-frequency load points and their conjugate targets;
- constant Q, the swept band, overlays and markers;
- copying out, and pasting a schematic in — including **which schematics are compatible**, stated as the
  five rules brief 7 enforces rather than as "simple cascades";
- the `smith` verb.

### `R-smith11-2` — the figures

Generated by the `UiArtworkGenerator` / `FigureCatalog` path, never hand-drawn and never screenshotted.
The minimum set: a chart with three element trajectories and their grippers; the same with the constant-Q
arcs on; a network strip both ways round, showing the mirror; a copied schematic as it lands in a `.csch`.

**Check the figures with `Svg.Skia`, not `qlmanage`** — `qlmanage` forces a square canvas and crops, so a
complete figure reads as clipped. Rasterise and read `Picture.CullRect`.

**And classify the churn before reporting it.** A DocGen run reporting hundreds of changed `.svg`s is
almost always id-churn, not real change — the id counter is **hex**, so a `\d+` pattern mis-classifies it.
Regenerate in a worktree at HEAD to separate your own drift from the ~67 one-pixel figures HEAD itself
reproduces.

## 2. `R-smith11-3` — the example

One example, added the way the other six were: a folder under `examples/` and a row in `examples.json`
(`Folder`, `Title`, `Summary`). It appears under Tools ▸ Examples automatically.

It should be **a real narrowband match that someone would actually do** — a low-impedance device input,
complex and stated over three frequencies, matched to 50 Ω with an L and a shunt C, with the load points
showing the band edges coming apart. Not a demonstration of every element type; a demonstration of the
idea.

Its `README.md` says what the design is, what to drag, and what to watch when you drag it. **If any
analysis setting was chosen for speed rather than for accuracy, the README states the alternative and the
numbers it gives** — that is a standing rule for every example in this repository.

## 3. `R-smith11-4` — drive it as a user, and fix what that finds

Open the tool with no workspace. Build a match. Drag every gripper. Change the design frequency. Mirror
the strip. Copy into a schematic and run it. Paste one back. Import an `.s1p`. Save, close, reopen. Open
it from the project tree. Set it as the On Launch action and relaunch.

Each defect that falls out gets **a test that fails at HEAD**, then the fix. Record every one in
`src/Ui/RESOLVED.md` with what it actually was — railRF's equivalent round found six, *none of which
reported a failure*, and that is the shape this kind of pass has.

## 4. `R-smith11-5` — the closeout

- `docs/design/smith-chart.md`'s status line: **PROPOSED → BUILT**, with the date and a per-brief note of
  what shipped, following `railrf.md` §6.1.
- **Answer or re-file the open questions.** §12 of the note carries Q-10 … Q-16. Each one is now answerable
  from the built tool: whether `F_ref` should track the design frequency, whether `S1P` earned its place,
  whether the active-parameter rule reads well in the hand, whether the load-point gripper surprises, and
  whether the generator panel should have followed the mirror. **Record the answer and the evidence**, not
  just the answer.
- **Grep for commercial vendor and PDK names** across everything this series added, before anything is
  committed, and report what was removed. The repo's standing rule; the only permitted exception in the
  whole tree is the `.kicad_pcb` extension.
- `docs/design/project-file-formats.md` gains its `.csmith` row.
- The CLI reference page gains `smith` (brief 10 adds it to `cli.md`; this brief checks the page
  regenerated).

## 5. The gate

- **DocGen runs clean**, and the churn is classified and reported — not "300 figures changed".
- **The example opens, drags and simulates**, driven headlessly: a test that opens the example `.csmith`,
  evaluates it, and asserts the documented load impedance. An example that is wrong is worse than no
  example, because it is the first thing someone copies.
- **`examples.json` and the folder agree** — the existing examples test already covers this shape.
- **Every defect found in `R-smith11-4` has a test that failed at HEAD.**
