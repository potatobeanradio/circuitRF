# Brief SAR-1 — openEMS 0.37.0 final, and the reference set from openEMS's own examples

**Series:** `brief-sar-0-overview.md` (L2, L3, L4) · **Tag:** `R-sar1-<m>`
**Depends on:** —
**Area:** `src/Design/Em3d/SolverDiscovery.cs` (the validated openEMS entry), `testdata/em3d/f0` (re-run),
`testdata/sar/openems-ref/` (new), `docs/design/sar.md` (new, §1–§3)

---

## 1. Goal

Before circuitRF computes any SAR, have the numbers it must reproduce. Those numbers are produced by **openEMS's own
examples, run as their authors wrote them**, on the version circuitRF validates, and committed as fixed data. Every
later phase gates against this set. `testdata/em3d/f0` is the precedent for every rule below.

## 2. Requirements

**R-sar1-1 — Validate openEMS 0.37.0 final.** Replace the `0.37.0-rc3` entry in `SolverDiscovery`'s validated list
with the 0.37.0 release (its git hash, CSXCAD's hash, and the release tags that upstream's Windows archive prints
instead). Re-run `testdata/em3d/f0` and every `openems-goldens` case on it, as the comment on that entry requires.
Any number that moves goes into `docs/design/em-3d-f0-findings.md` with its cause. **Ask the owner before keeping an
rc3 entry beside the final one.**

**R-sar1-2 — The examples, run unmodified.** These openEMS 0.37.0 examples:

| Example | Interface | What it is |
|---|---|---|
| `Dipole_SAR` | Python | 1 GHz dipole 20 mm from a three-layer ellipsoid head; S11, Zin, accepted and radiated power, 10 g SAR, power budget |
| `MRI_Loop_Coil` | Python | 7 T (298 MHz) 80 × 60 mm loop, three 5.4 pF lumped capacitors, 2.5 Ω feed, beside the bundled ellipsoid head phantom; S11, Yin, local SAR planes, B1± planes |
| `MRI_LP_Birdcage` | Octave | 3 T (128 MHz) 8-rung low-pass birdcage, quadrature feed (1, −j); needs Octave on the developer machine (O5) |
| the analytic SAR tests | Python | `test_sar_analytic.py`'s uniform 4 × 4 × 4 phantom, run as a check on the installed `sar_calc` |

Each runs **with its physics untouched**. A wrapper under `testdata/sar/openems-ref/tools/` (never under `src/` or
`tools/`, the GPL boundary of `testdata/em3d/f0/README.md`) runs the script with `runpy`. It replaces only what stops a
headless run: matplotlib on a non-interactive backend with figures saved rather than shown, and the geometry viewer
call stubbed out. **The wrapper changes no parameter.** If a script cannot run without a physics change, stop and
report it.

**R-sar1-3 — What is kept.** Per example, under `testdata/sar/openems-ref/<example>/`:
- the CSXCAD XML the script wrote — **the grid lines in it are what SAR-7 and SAR-8 run on**;
- port results over the script's own frequency vector (S11, Zin or Yin, accepted power), as `.npy`;
- the SAR output the script reads (`SAR_10g.h5` for the dipole; the local SAR planes for the loop), converted to
  `.npy` with its mesh lines in metres, plus `maxSAR`, total power and mass;
- the B1+ and B1− planes the loop script computes, per √W, as `.npy`;
- the scalars the script prints (power budget, peak SAR per watt, whole-phantom SAR), in `summary.json`;
- for the dipole, the **raw** `DumpType 29` file as well, so SAR-5 can run its engine and `sar_calc` on the same input.
  **Its size is measured before it is committed.** Above about 20 MB, ask the owner.

The `.h5` → `.npy` conversion uses openEMS's own Python reader (`readSAR`, `HDF5Dump`) inside the wrapper, so the
reference does not depend on SAR-4's reader. The bundled phantom `.h5` files are **not** committed (L3).

**R-sar1-4 — Provenance.** `testdata/sar/openems-ref/README.md`, in `testdata/em3d/f0/README.md`'s form: machine, OS,
openEMS, CSXCAD, HDF5, Python and Octave versions; the exact command per example; wall time; and the rule that
**nothing here is regenerated by circuitRF**.

**R-sar1-5 — Run-to-run spread.** Run `Dipole_SAR` three times and record the spread of psSAR10g and accepted power.
With `--exact-endcriteria` the runs should be identical; if they are not, the spread is the floor under §4's
tolerances. Record it in the design note.

**R-sar1-6 — The design note opens.** `docs/design/sar.md` §1: what SAR, psSAR and B1± are, with the formulas
(local SAR = σ|E|²/(2ρ) for peak phasors; B1± per L8, derived once). §2: what openEMS 0.37.0 offers (overview §2),
with the dump types and `sar_calc`'s options. §3: this reference set and its numbers.
