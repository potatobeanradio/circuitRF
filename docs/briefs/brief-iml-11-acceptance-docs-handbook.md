# Brief IML-11 — Acceptance, the user page, the design note, the developer handbook

**Series:** `brief-iml-0-overview.md` (§4, L11) · **Tag:** `R-iml11-<m>`
**Depends on:** IML-1 … IML-10
**Area:** `docs/design/schematic-vision.md`, `tools/schematic-ml/README.md` + `LABELLING.md`, the Create from Image user
page (schematic sections and "Pasting"), `src/Vision/Models/MODEL_CARD.md`, `src/Design/RESOLVED.md`,
`examples/Schematic from Image` (re-authored if its reading changed)

---

## 1. Goal

Measure the shipped reader against overview §4, tell users what it does in plain words, and leave a handbook good
enough that **another circuitRF developer can add pictures, retrain and ship new weights** without this series'
context — the owner's reason for putting the training code in the repository.

## 2. Requirements

**R-iml11-1 — The numbers.** Design note §13: every §4 target against the shipped model — held-out real pictures per
family and overall, the datasheet/web corpus, the size targets, generated pictures, IMF-1's committed pictures, time on
the owner's Debug build (from a scratch harness, once — no timing test), the shipped size. Each miss is listed with its
picture id, what went wrong, and whether more data, a style pack, or a class-list change would fix it.

**R-iml11-2 — The user page.** The schematic parts of the Create from Image page say what the reader is (a trained
reader built into circuitRF, nothing to install, nothing sent anywhere), what reads well and what does not (hand-drawn,
photographs of paper, very small or blurred pictures), that parts are placed at the picture's size over the picture,
and what the selection after a paste means. No change history (the owner's rule for user docs). Figures that show the
dialog or a paste are regenerated by DocGen at the end of the series — the owner runs DocGen; this phase edits sources
and lists the figures owed.

**R-iml11-3 — The handbook.** `tools/schematic-ml/README.md`, complete:
1. what the system is (two networks, the assembly, where each piece lives) and the data rules (L1, L2, L8);
2. setup: Python version, `pip install -r requirements.txt`, `$CRF_ML_DATA`, fetching fonts;
3. **adding pictures:** import, pre-label with the shipped model, annotate, contact-sheet review;
4. **adding a convention:** writing a style pack, previewing it beside real pictures;
5. **adding a class:** `classes.json`, its circuitRF mapping, generator support, the C# mapping test;
6. generating data, training (configs, expected time on an Apple-silicon Mac), reading `evaluate.py`'s report;
7. **shipping:** `export.py`, `ship.py`, the model card, the tests to run (`tests/Vision.Tests`, the image classes),
   and the rule that a model ships only when its test numbers beat the current one's;
8. troubleshooting: the export refusing an operator, a probe mismatch, a split violation.

**R-iml11-4 — The model card.** `MODEL_CARD.md` final for the shipped version: intended use (schematic pictures pasted
or imported into circuitRF), out of scope (§8 of the overview), data by family id and count, numbers, known
weaknesses — no editor, vendor or part-maker names (L2).

**R-iml11-5 — Vendor-name sweep.** The CLAUDE.md pre-commit grep run over everything this series added — briefs,
`tools/schematic-ml/`, `tools/SchematicSynth/` including every style pack, `src/Vision/`, tests, docs, the model card,
the JSON metadata inside the `.crfnn` files. Anything found is removed and reported in chat.

## 3. Gates

- The image test classes and `tests/Vision.Tests` green (targeted run).
- The handbook walked once from a clean clone by a fresh agent with only the handbook: set up, generate 100 pictures,
  run one training step and an export, run the parity test. What it had to guess is fixed in the handbook.
- The owner reads design note §13 and the user page.

## 4. Not in this phase

New model features. DocGen (the owner runs it). Pushing.
