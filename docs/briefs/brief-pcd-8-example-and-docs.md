# Brief PCD-8 — The example, the docs, the screenshots and the acceptance check

**Series:** [PCell Designer](brief-pcd-0-overview-and-contract.md) · **Tag:** `R-pcd8-n`
**Area:** `examples/PCell Designer/` and `examples/examples.json`; `docs/user/src/reference/pcell-designer.md` (and
`_nav.txt`), `file-formats.md`, `em-cells.md`, `components.md`, the user `cli.md`; `docs/design/pcell-designer.md`; the
regenerated user HTML; every `RESOLVED.md`; `tests/Ui.Tests/PCellDesigner/Pcd8*.cs`, `testdata/pcell-designer/pcd8/`
**Depends on:** every other PCD lane. It runs last and closes the series.

---

## 0. What this adds

The series made a schematic of primitives a parameterised cell. This lane shows it to a user: one example that a new
user opens and runs, a reference page, a design note that keeps the series' decisions, the screenshots, and the one
end-to-end test (PCD-0 §8) that every lane's code has to pass together.

## 1. Requirements

- **`R-pcd8-1` — the example.** `examples/PCell Designer/` holds the §8 cell `PadTee` and a bench that places it twice
  (`Lpad` 200 µm and 400 µm) in a 50 Ω line, a `.cdd` the app renders, and a short README. No results are committed.
  `circuitrf check` passes on it. A row in `examples/examples.json`.
- **`R-pcd8-2` — the docs.** The user page `pcell-designer.md` in the site's navigation, written like the other
  reference pages; the design note `docs/design/pcell-designer.md` (S1-S8, each lane's decisions, Possible
  enhancements with reasons); the `.cpcell` entry in `file-formats.md`; `EmCopper` in `em-cells.md`; `MSHAPE` in the
  components catalogue; the `pcell` verb in the user `cli.md`, from PCD-7's text.
- **`R-pcd8-3` — screenshots and HTML.** The designer window and the placed bench through `tools/UiSnapshot` (the
  headless recipe in PCD-6's report), then the user HTML regenerated by `tools/DocGen`.
- **`R-pcd8-4` — the acceptance check.** `tests/Ui.Tests/PCellDesigner/Pcd8AcceptanceTests.cs`, PCD-0 §8's six steps
  through the functions the window and the verb call. The real Planar run is made once on the example with
  `circuitrf opt` (`em=correct`) and its result reported, not committed.
- **`R-pcd8-5` — RESOLVED.md.** The lanes' findings go into the `RESOLVED.md` of the area they touched.

## 2. Decisions

- **D1 — One cell, used everywhere.** The example's `PadTee` is the §8 cell, so the test, the screenshots, the docs and
  the Planar run all show the same copper. The test builds its own copy in a scratch folder, so the example stays
  untouched by it.
- **D2 — A failure in another lane's code is reported, not fixed here.** A step that fails because of another lane's
  file is named with its exact message; this lane edits only its own files (PCD-0 §6).

## 3. Tests

`tests/Ui.Tests/PCellDesigner/Pcd8AcceptanceTests.cs`, one test, the six steps in order.
