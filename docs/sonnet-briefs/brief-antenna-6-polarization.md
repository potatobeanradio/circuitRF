# Brief — ANT-6: polarization — Ludwig-3 co/cross, axial ratio, sense

**Series:** `brief-antenna-0-overview.md` §4. **Depends on:** ANT-4. **Blocks:** nothing.

Short arithmetic over `Etheta` and `Ephi`, with one definitional decision that has to be made
explicitly and then said in the UI.

---

## 1. The decision: Ludwig's third definition, named where the number appears

Ludwig's first, second and third definitions of cross-polarization give **different numbers for the
same antenna**. The third is the antenna-measurement standard and is what a range reports, so it is
what circuitRF should compute.

**That is not the interesting half.** The interesting half is that a cube called `CrossPolDb` with no
qualifier is a number a user cannot reproduce, cannot compare against a measurement, and cannot argue
with. So:

- the cube names carry the definition (`CoPolLudwig3Db` / `CrossPolLudwig3Db`, or the definition sits
  in the cube's own note — either, but not neither);
- the panel and the trace picker say it in words;
- if a second definition is ever added, it is an additional cube, never a mode that silently changes
  what an existing cube means.

Given a reference polarization angle φ₀ (the nominal linear polarization direction):

```
E_co    =  E_θ cos(φ − φ₀) − E_φ sin(φ − φ₀)
E_cross =  E_θ sin(φ − φ₀) + E_φ cos(φ − φ₀)
```

**Derive the exact form against the convention `SpectralGreens` and ANT-4 actually use**, and gate it
per §4 — do not lift the algebra from here without checking the sign convention it lands in.

## 2. φ₀ comes from the structure, and is reported

The reference angle is a property of the antenna, not of the plot. Two sources, in order:

1. **User-named**, on the EM setup. Always available, always wins.
2. **Derived from the solved current distribution** — the dominant current axis, weighted by |J|² —
   and **reported**, in the same words the mesher reports a direction it inferred.

**Where the derivation is ambiguous, refuse rather than pick.** A circularly-polarized or
dual-fed structure has no single linear reference, and cross-pol against an invented one is a number
about the invention. That case is exactly what §3 is for, so the refusal has somewhere to point.

## 3. Axial ratio and sense, in the same phase

Same two complex numbers, and they cover circularly-polarized patches — corner-truncated, dual-feed,
truncated-corner — which is a large fraction of why anyone simulates a patch at all. Doing them later
means writing the same decomposition twice.

| cube | kind | note |
|---|---|---|
| `AxialRatioDb` | Real | `[freq, theta, phi, port]`. ∞ (or a stated large value with its meaning) for pure linear — decide and state which. |
| `PolarizationSense` | Real | LH/RH as a signed scalar, with the convention (IEEE, looking along propagation) named in the note. |
| `CoPolLudwig3Db`, `CrossPolLudwig3Db` | Real | Needs φ₀; refuses without one. |

**Sense conventions differ by a sign between disciplines.** Name the one taken, in the note, once.

## 4. The cross-pol floor is set by the mesh, and the tool must say so

**Cross-polarization is generated by asymmetry.** On a nominally symmetric patch the physical cross-pol
is very low, and what the solver reports will be dominated by the *mesh's* own asymmetry — a
staircased boundary is not symmetric, and neither is a grid whose lines were placed by an attractor at
one rim.

So a reported cross-pol of −45 dB may be −45 dB of mesh. This must not be discovered by a user.

**Two things are required, and the second is the real one:**

1. A note, wherever cross-pol is reported, that the floor is mesh-limited.
2. **A measurement, in the write-up**: cross-pol on a symmetric patch at three mesh densities and with
   staircase vs conformal boundary cells. If the number moves with the mesh, that is the floor and it
   should be quoted as such. If it does not move, that is a stronger result and it should be quoted
   too.

This also has a consequence worth stating for the series: **conformal boundary cells matter more for
antenna work than for filter work**, and not only for cross-pol. Staircase quantisation of the patch
length at a 2.4 mm cell on a 41.3 mm patch is a ~6 % length error and therefore ~6 % in resonant
frequency, which is the headline number for an antenna. `PlanarBoundaryCells` ships `Staircase` by
default and the reason recorded is reproducibility of every measured number in that directory —
that reason stands, so this brief does **not** flip the default. It records the argument, and ANT-12
should pick conformal for the shipped example.

## 5. Gates

- **An analytic linear source** — a single x-directed current element over the slab — has zero
  Ludwig-3 cross-pol in the principal planes by symmetry. That is an exact statement and it is the
  first gate.
- **A known circular case**: two orthogonal elements in phase quadrature give axial ratio 0 dB and a
  known sense. Both signs, so the sense convention is pinned rather than assumed.
- **Pure linear gives the stated axial-ratio sentinel**, whatever §3 decides it is.
- **φ₀ refuses when ambiguous**, and reports when derived.
- **The mesh-floor measurement is reported** (§4), not gated.
- The definition appears in the cube name or note, asserted.
- `RESOLVED.md` write-up in `src/Engine/Mom`; `CLAUDE.md` gains the chosen definition and the sense
  convention — both are things that stay true tomorrow and both are things that would be re-derived
  wrongly if they were not written down.

## 6. Must NOT

- **Do not report cross-pol without the definition attached.**
- **Do not add a "definition" mode that changes what an existing cube means.** A second definition is a
  second cube.
- **Do not derive φ₀ silently when it is ambiguous.**
- **Do not clamp axial ratio** to hide the linear case; give it a stated sentinel.
- **Do not flip the `PlanarBoundaryCells` default** on the strength of §4. Record the argument.
